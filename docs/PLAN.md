2026-09-18 기준. 목표 제출일 9/20까지 달력 기준 2일이며 공식 마감 시각은 미확인입니다.
현재 분석 범위는 [EXPANDED_RULES.md](EXPANDED_RULES.md), 완료 증거는 [PROGRESS.md](PROGRESS.md)에 있습니다.

## 우선순위

1. **제출 환경 확인:** 채점 OS/아키텍처, Docker 사용·이미지 tar 반입 여부, 용량 제한과 제출 경로.
   사용자 제공 안내에서 오프라인·디렉터리 일괄 처리·비대화형 진입점은 필수로 확인했습니다.
2. **오프라인 패키징:** Python·Slither·solc와 전이 의존성을 고정하고 라이선스/고지를 수집합니다.
   Docker 실행은 사용자에게 허용 확인. Dockerfile·설치 버전 lock·solc 해시 검증·실행 안내를 준비했습니다.
   현재 PC에 Docker가 없어 실제 이미지 빌드/오프라인 컨테이너 검증과 tar 생성은 남아 있습니다.
3. **최종 재현:** 기존 가상환경이 없는 환경에서 네트워크 차단·2CPU/4GB로 실행합니다.
   정상/위험/오류/큰 입력을 섞고 JSON·자식 프로세스 종료·전체 10분 제한을 확인합니다.
4. **출력과 제출 자료:** 중복 evidence, 파일별 안전/위험 설명을 다듬습니다.
   실행 README, 지원/미지원 범위, 실험 결과, AI/본인 기여, 공통 안내의 필수 자료를 완성합니다.

9/18은 제출 후보 준비, 9/19는 통합 검증·수정·자료 정리, 9/20은 최종 확인·제출을 목표로 합니다.
실제 가용시간은 미확인이며 날짜별 완료를 보장하지 않습니다. 웹과 추가 규칙 확대는 후순위입니다.

## 완료 기준

- 입력 디렉터리 바로 아래의 모든 .sol마다 결과 하나, stdout은 유효한 JSON 배열 하나.
- 개별 실패/timeout을 UNCERTAIN으로 격리하고 미처리 결과까지 전체 예산 내 출력.
- 채점 중 설치·다운로드·외부 API 없이 실행. 제출된 고정본과 검증본을 식별 가능하게 기록.
- 공개/개발 변형/독립 평가를 구분하고 실제로 실행한 결과만 보고.
- 사용자가 정상/위험 한 쌍의 권한 → 검사 → 상태 변경 → 사용자 영향을 직접 설명.
