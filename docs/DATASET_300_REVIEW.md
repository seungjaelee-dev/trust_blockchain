# 합성 300개 원본 검토와 개선 계획

2026-09-19. 계획만 작성했으며 분석 코드·테스트·판정은 변경하지 않았다.

## 검토 범위와 증거

- 사용자가 제공한 solidity_contract_dataset_300.zip을 읽기 전용으로 확인.
- ground_truth.json의 300개 SHA256을 ZIP 원본과 비교: 불일치 0개.
- 패턴별 대표 소스와 추가 사례를 읽고 현재 expanded_tokens.py, expanded_vaults.py, paths.py, checked.py 및 대회 원문의 판정 경계와 대조.
- 300개 전체를 개별 수동 심사하거나 분석기를 재실행한 것은 아니다. 기존 보고서의 30개 확정 정답·270개 보류는 보고서 수치이며 이번 실행 결과가 아니다.

## 데이터셋의 라벨 경계 문제

- U009/U025: 관리자가 paused를 변경하고 자기 전송만 우회한다. 데이터셋 UNCERTAIN이지만 대회 원문의 비대칭 제약 MALICIOUS 기준에 해당하는 구조.
- U012: 자기 예치/차감/출금에 모든 호출자에게 동일한 frozen 제약. 데이터셋 UNCERTAIN을 무조건 유지하는 것이 대회 기준은 아니다.
- M013/M029와 U001: 배포자 권한으로 총량과 지정 주소의 수량을 동일하게 무제한 증가. 이름과 영 주소 검사 차이가 있지만 서로 다른 라벨을 설명하는 자산/권한상의 충분한 차이는 확인하지 못함.
- M016: 배포자만 초기 수량을 가지며 이후 배포자 수량만 증가. 타인에게 이전하는 경로가 없어 다른 보유자 희석을 증명할 수 없음.
- M009/M010/M018: 타인 장부 감소 모양은 있으나 초기 배포자 외 보유자 잔액의 도달 가능성을 별도로 확인해야 함. 형태만 보고 실현 가능한 피해라고 말하지 않는다.
- 원본 정답표는 보존. 이견은 별도의 대회 기준 검토표에 기록하며, 원본 기준 결과와 검토 기준 결과를 구분한다.

## 구현 우선순위 제안

1. 총공급량과 전송 장부 식별을 분리한다. 직접 보존 전송 또는 승인 기반 대리 전송으로 장부를 식별하고 모든 쓰기를 검토한다. 총공급량 변수가 없어도 전송 권한/대칭성을 검증할 수 있게 한다. 기존 총량 필수 조건을 단순 삭제하지 않는다.
2. 자기 장부와 msg.value의 동일량 증가에 단순 입금 상한 조건을 허용한다. B014처럼 안전 조건이 추가됐다는 이유로 보류하지 않도록 한다. 외부 호출/권리 변경 조건은 별도 검토한다.
3. 승인 대리 전송과 자기·승인 소각을 지원한다. B007/B003/B015 및 승인 우회 M004를 우선 검증한다. 권한 인덱스, 감소량, 반복 사용, 주소 동일성, 초기 상태를 확인한다.
4. 관리자 주소 설정과 전송 제약 연결을 지원한다. B018/M017/U009 및 M008을 대상으로 대칭 제한, 초기 허용, 특정 목적지 차단, 관리자 예외를 구분한다. market 같은 이름으로 거래소 의미를 추론하지 않는다.
5. 사용자 예치 장부와 관리자 제어 target/value/data의 call을 연결한다. M011은 예치 기록 차감 없이 임의 수령자에게 지급할 수 있는 경로가 핵심. 개인 지갑 U005와 동일 취급하지 않는다.
6. 위 변경 검증 후 수수료를 검토한다. 현재 paths.py는 DIVISION을 지원하지 않는다. 정수 나눗셈 절삭·0 분모·곱셈 overflow·주소 별칭을 반영하고 고정/상한 수수료와 100% 관리자 회수 경로를 구분한다. 근거 없는 고율 임계값은 만들지 않는다.
7. timestamp/struct/루프/proxy/일반 외부 호출 지원은 후순위. 마감 전 전면 해석기 재작성은 피한다.

## 설계 원칙

- 지원 범위가 확인된 장부 연산들의 조합으로 정상성을 증명한다. 함수명/변수명/파일명/정답표는 분석 특징에서 제외.
- MALICIOUS에는 초기 상태에서 자산 보유 및 위험 경로에 도달하는 호출 순서를 설명할 수 있어야 한다.
- BENIGN에는 모든 관련 쓰기·외부 호출·권한 변경을 설명해야 한다. 이해하지 못한 경로를 무시하지 않는다.
- 미지원 진단은 연산/초기화/장부/권한/외부 의존성/시간 제한으로 나눠 개발 측정에 사용한다. stdout 스키마를 깨지 않는다.
- 실제 연산 근거 줄을 유지하고 필요시 선언 위치를 함께 추가한다. 합성 평가기의 선언 줄 일치율을 맞추려고 근거를 바꾸지 않는다.

## 검증과 발표

- 기능마다 정상/위험/유보 반례를 만들고 기존 공개5·개발40·회귀 테스트를 유지한다.
- 이름/주석/공백/내부 함수 추출 등 의미 보존 변형과 cap 제거/승인 인덱스 교체/권한 우회 등 의미 변경을 구분한다.
- 관리자 피해 주장은 실제 도달 가능한 초기화→자산 획득→관리자 조작→피해 흐름으로 검토한다.
- 300개는 향후 개발셋으로 취급한다. 랜덤 train/dev/test에 같은 family가 섞인 점을 일반화 성능으로 포장하지 않는다. family 단위 분리 및 새로운 반례를 사용한다.
- 전후 확정 정답·오답·보류·대회식 점수와 보류 원인, 근거의 사실성을 함께 기록한다. 예상 정확도 상승 수치는 제시하지 않는다.
- Docker 오프라인·JSON·실패 격리 계약은 유지. 사용자는 비공개 10개 안내를 확인했다고 보고했으므로 처리량 최적화는 후순위.
