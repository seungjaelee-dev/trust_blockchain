# 검증 자료

제출 설명에 필요한 대표 자료만 보존합니다. 분석 패키지는 이 결과나 정답 목록을 읽지 않습니다.

| 파일 | 용도 |
| --- | --- |
| [release-crosscheck.json](release-crosscheck.json) | 최종 교차검증: 제출 후보 파일·이미지 해시, 캐시 없는 빌드, 전체31 테스트와 혼합60개 실행 |
| [submission-integration.json](submission-integration.json) | 같은 판정 코드의 정상·위험·오류 혼합60개 실제 JSON 출력 예시 |
| [slither-baseline.json](slither-baseline.json) | 대표10개에서 기본 Slither가 낸 경고; 자체 계층의 역할을 설명하는 비교 자료 |
| [stage1-corpus-comparison.json](stage1-corpus-comparison.json) | 합성300개 비교와 추가 탐지 실험을 철회한 근거 |

## 최종 실행 확인

- Git 제출 후보147개만 새 폴더에 복사하여 온라인 준비 단계에서 캐시 없이 빌드했습니다.
- 새 이미지의 네트워크 차단·2CPU/4GB·추가swap없음 조건에서 전체31 테스트248.133초, 혼합60개83.554초로 통과했습니다.
- 혼합60개는 공개5 + 개발40 + 장부14 + 문법 오류1입니다. 기대 판정, 원본 schema, 이유와 위치 연결, 오류 격리, timeout·자식 종료를 검사했습니다.
- 별도6개에서는 공개 표본의 파일명·주석 라벨·줄 위치를 바꾸고 한글·공백 경로 및 문법 오류를 확인했습니다.
- 코드·패키징의 검증 기록이며 비공개 정확도나 모든 설명의 의미를 증명한 결과는 아닙니다. 개발에 사용한 표본은 독립 평가셋으로 부르지 않습니다.

## 합성300개에서 확인한 한계

추가 탐지 확장 전후 모두 **정답40·오답5·보류255**, 판정 변화0개였습니다. 10개씩30묶음으로 비교했으며 원본 라벨과 입력 해시를 보존했습니다. 일부 라벨은 대회의 권한·자산 귀속 경계와 다르다고 검토했지만 정답표를 임의 변경하지 않았습니다. 추가 탐지 확장은 철회했으며 시간 예산과 설명 출력 개선은 유지했습니다.

이 기록을 남긴 이유는 좋은 결과만으로 일반화 성능을 주장하지 않기 위해서입니다. 과거 비교 이미지가 현재 제출 이미지라는 뜻은 아닙니다.

## 재현과 기록 관리

전체 회귀는 [Docker 개발 안내](../DOCKER.md)의 명령을 사용합니다. WSL 개발 Python이 준비되어 있으면 다음 명령으로 혼합 입력과 위치 대응을 다시 검사할 수 있습니다.

```bash
python tests/evaluate_ledger_docker.py --image trust404-track1:submission \
  --output final-check \
  --reporting-baseline docs/experiments/submission-integration.json
```

기록된 해시와 경로는 **검증 당시** 기준입니다. 이후 문서 정리로 옮겨진 파일도 목록에 있을 수 있습니다. 문서 정리만으로 새 코드 실행을 했다고 기록하지 않습니다. 중간 로그와 과거 문서 사본은 Git에서 제외되는 로컬 `results/`에 보관합니다.
