# 분석 원리와 지원 범위

이 분석기는 코드를 실행하지 않고 solc와 Slither가 만든 구조를 읽습니다. **누가 호출하는가 → 어떤 조건을 통과하는가 → 어떤 장부·자산이 바뀌는가 → 사용자에게 어떤 영향이 있는가**를 연결합니다.

## 파일에서 판정까지

`scripts/analyze.py → cli.py → worker.py → verdict.py → rules/ → reporting.py → JSON`

- `cli.py`가 입력 목록과 시간 예산을 관리하고 파일마다 worker를 실행합니다.
- `worker.py`가 solc·Slither를 호출합니다. 컴파일 실패는 해당 파일의 `UNCERTAIN`입니다.
- `verdict.py`가 컨트랙트마다 일곱 규칙을 적용하고 파일 전체를 집계합니다.
- `reporting.py`가 결론과 함수별 조건·상태 변경·호출 순서를 원본 위치에 연결합니다.

지원 범위 전체를 확인한 안전 근거가 있어야 `BENIGN`, 경고 대상 경로의 충분한 증거가 있으면 `MALICIOUS`, 핵심 경로를 해석하지 못하면 `UNCERTAIN`입니다. 같은 컨트랙트에서 다른 규칙이 미지원이라는 이유만으로, 전체 안전성을 확인한 규칙의 결과를 무효화하지는 않습니다. 다만 파일 안의 다른 컨트랙트까지 확인하지 못했다면 파일 전체를 정상으로 확정하지 않습니다.

## 일곱 판정 규칙

| 파일 | 확인하는 관계 |
| --- | --- |
| `supply.py` | 소유자 발행의 공급량·잔액 증가와 강제되는 고정 공급량 상한 |
| `fixed_supply.py` | 고정 공급량, 자기 잔액 전송, 승인 한도 검사와 실제 차감 |
| `transfer_restrictions.py` | 관리자 초기 허용·목록 변경 권한·일반 보유자의 전송 제한 |
| `delegatecall.py` | 사용자 ETH 예치와 관리자가 선택하는 대상·데이터의 임의 실행 |
| `expanded_tokens.py` | 분기·내부 호출을 포함한 발행 상한, 승인, 지원하는 정지·관리 경로 |
| `expanded_vaults.py` | 예치·출금·관리자 회수, 입금 상한, 임의 지급, 제한된 재진입 패턴 |
| `ledger_operations.py` | 총공급량 없는 전송 장부, 자기/승인 소각, 지원하는 비대칭 제한 |

`common.py`, `linear.py`, `paths.py`, `checked.py`는 규칙이 사용하는 보조 코드입니다. 선언을 연결하고, 조건·쓰기·호출 순서를 수집하며, checked 산술 실패와 실행 불가능한 경로를 구분합니다. 이름이나 주석 LABEL로 판정하지 않습니다.

## 중요한 정상·위험 경계

1. **발행:** 한 번에 발행할 양만 제한하면 반복 발행의 총량을 막지 못합니다. 실제 증가량을 더한 공급량의 최종 상한과 다른 발행 경로도 확인합니다. 소유자 발행이어도 코드가 고정 상한을 강제하면 대회 기준상 그 자체로 악성이 아닙니다.
2. **승인:** 타인 잔액을 옮기려면 본인 확인 또는 실제 사용량만큼 차감되는 승인이 필요합니다. 검사만 하고 승인을 남겨 두면 반복 사용으로 한도를 넘길 수 있습니다.
3. **제한:** 모두에게 같은 정지와 관리자만 우회하는 제한을 구분합니다. 목록이 존재한다는 사실만으로 악성이라고 하지 않습니다.
4. **금고:** 입금으로 생긴 사용자의 권리와 출금·관리자 송금을 연결합니다. 예치 경로 없는 force-send ETH는 대회 원문의 특수 귀속 가정을 따릅니다.
5. **재진입:** 송금 전에 장부를 차감하는지, 잠금이 있는지, 사후 checked 차감으로 초과 지급 전체가 취소되는지 살핍니다. 송금 후 장부를 0으로 덮는 경우와 구분하며 모든 재진입 유형을 해결한다고 주장하지 않습니다.
6. **위치와 설명:** 같은 위험의 중복 결론은 병합하고 서로 다른 위험·함수·분기는 남깁니다. 성공 조건은 거래 전체가 성공할 조건이며 항상 변경 전에 검사한다는 뜻은 아닙니다. [출력 읽는 법](REPORTING.md)을 참고하세요.

## 지원 한계

일부 분기·내부 호출·같은 파일의 상속을 지원합니다. 함수당 경로64개, 노드 예산400, 호출 깊이8을 넘으면 보류합니다. 일반 SMT 증명기나 완전한 기호 실행기는 아닙니다.

루프·재귀·assembly·unchecked·uint256 외 산술·일반 외부/라이브러리 호출·import·복잡한 상속 생성자·storage 별칭·일반 proxy와 다중 자산 DeFi는 미지원이거나 지원이 제한됩니다. 무시할 수 없는 추가 쓰기·호출을 안전으로 덮지 않습니다. 기본 파일60초/전체540초이며 초과한 입력도 JSON에 보류 결과를 남깁니다.

합성300개에 맞춘 추가 탐지 실험은 이전·확장 버전의 판정 차이가 없어 철회했습니다. 그 기능을 현재 지원한다고 설명하지 않습니다. [검증 자료](experiments/README.md)에 실제 결과와 한계를 남겼습니다.

## Slither와 자체 기여

Slither는 AST·CFG·SlithIR을 제공하며, 기본 detector의 경고를 곧바로 대회 라벨로 바꾸지는 않습니다. 자체 계층이 자산 도달·권한·상한·승인·실행 순서를 대회 기준과 연결합니다. 대표10개에서 관찰한 기본 경고는 [비교 원본](experiments/slither-baseline.json)에 있습니다. 이 비교를 일반적인 성능 우위로 해석하지 않습니다.
